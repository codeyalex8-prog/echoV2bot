# Sending in-game commands safely
The API can run commands in your server, for example an announcement. This is powerful, so we add guard rails. **commands/announce.js**
```js
const { SlashCommandBuilder, PermissionFlagsBits, MessageFlags } = require('discord.js');
const { erlc } = require('../src/erlc');

module.exports = {
  data: new SlashCommandBuilder()
    .setName('announce')
    .setDescription('Send a server-wide message in ER:LC')
    .setDefaultMemberPermissions(PermissionFlagsBits.ManageMessages)
    .addStringOption(o => o.setName('message').setDescription('What to announce').setRequired(true).setMaxLength(150)),

  async execute(interaction) {
    const text = interaction.options.getString('message').replace(/[\r\n]+/g, ' ').trim();
    if (!text) return interaction.reply({ content: 'Message is empty.', flags: MessageFlags.Ephemeral });

    await interaction.deferReply({ flags: MessageFlags.Ephemeral });
    try {
      await erlc('/server/command', { method: 'POST', body: { command: `:h ${text}` } });
      await interaction.editReply('Announcement sent.');
    } catch (e) {
      await interaction.editReply(`Failed: ${e.message}`);
    }
  },
};
```
**The golden rules**
1. **Never pass raw user text as the whole command.** Build the command yourself (`:h ` + a cleaned message). Otherwise someone could type any admin command.
2. **Use an allow-list** when you let people choose commands:
```js
const ALLOWED = { announce: ':h', message: ':m' };
```
and only ever build from those keys.
3. **Restrict who can run it:** `setDefaultMemberPermissions` plus a role check in code for real safety.
4. **Strip line breaks and limit length.**
5. **Log every use** to a staff channel: who ran it, what was sent, when.
6. **Respect the rate limit.** Commands are limited to about one every five seconds per server, so queue them instead of firing several at once.

**Common errors**
- `500` or "no players": some commands need at least one player in the server
- `403`: wrong key
- Nothing happens in game: the command text may be invalid for your server's permissions

Checkpoint: `/announce` shows a message in your ER:LC server.
