# Hosting, safety and going live
**Run it 24/7:** a VPS with pm2 is the usual choice.
```
npm install -g pm2
pm2 start index.js --name erlc-bot
pm2 save && pm2 startup
```
**Multiple ER:LC servers**
Store one key per Discord server (or per ER:LC server) in your data file and pass it to the client. Our helper already accepts `key`:
```js
await erlc('/server/players', { key: data.servers[interaction.guildId].key });
```
Add `/setkey` for owners that saves the key, and **never echo the key back** in a message. Delete the owner's command message or use an ephemeral reply.

**Auto status message**
```js
setInterval(async () => {
  const s = await cached('/server').catch(() => null);
  if (s) statusMessage.edit(statusPayload(s)).catch(() => {});
}, 60000);
```
**Safety checklist**
- Server key only in `.env` or an encrypted database
- Every command that changes the game is staff-only and logged
- Cleaned input, allow-list for commands
- Caching and retry on 429, so you never hammer the API
- Errors are caught and shown politely (never a raw stack trace to users)
- `.env`, `data.json` and keys are not in Git
- Permissions on the Discord bot are minimal

**Monitoring:** log errors to a staff channel and alert yourself if the API fails several times in a row.

**Be a good API citizen:** do not scrape at high speed, follow PRC's rules, and expect some changes over time. Keep your code in small helper functions so updating one endpoint is quick.

**Where to go next:** warn and ban sync with `/server/bans`, automatic shift tracking, vehicle reports, a staff leaderboard, or a website dashboard.

Congratulations. You now know how an ER:LC bot is put together from the first request to production.
