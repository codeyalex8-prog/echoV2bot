# Step 8: Handling interactions
Discord sends an **interaction** every time someone uses a command, button or menu. Add this to **index.js** (before `client.login`), and import `MessageFlags`:
```js
client.on(Events.InteractionCreate, async interaction => {
  if (!interaction.isChatInputCommand()) return;

  const command = interaction.client.commands.get(interaction.commandName);
  if (!command) return;

  try {
    await command.execute(interaction);
  } catch (error) {
    console.error(error);
    const msg = { content: 'Something went wrong running that command.', flags: MessageFlags.Ephemeral };
    if (interaction.replied || interaction.deferred) await interaction.followUp(msg);
    else await interaction.reply(msg);
  }
});
```

**Why the try/catch matters**
Without it, one bug in one command can crash your whole bot. With it, the user gets a polite message and you get the error in your terminal.

**Test it**
1. Stop the bot (Ctrl + C) and start it again with `npm start`
2. In Discord run `/ping`. You should see **Pong!**

**Handy things on `interaction`**
- `interaction.user` is who used it
- `interaction.member` is that person as a server member (roles, nickname)
- `interaction.guild` and `interaction.channel` are where it happened
- `interaction.commandName` is which command

**Restart rule of thumb**
- Changed what a command **does** (`execute`)? Just restart the bot.
- Changed a command's **name, description or options** (`data`)? Run `node deploy-commands.js` too.

**Checkpoint:** `/ping` replies with the latency.
