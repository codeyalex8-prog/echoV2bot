# Step 13: Hosting, safety and next steps
Right now your bot only runs while your computer and terminal are open. To keep it online 24/7:

**Hosting options**
- **A VPS** (Linux server) with **pm2**: full control, great value
- **Bot hosting panels**: upload your files, set the start command `npm start`
- **A spare computer or Raspberry Pi** at home

**Running with pm2 on a server**
```
npm install -g pm2
pm2 start index.js --name my-bot
pm2 save
pm2 startup
```
Useful: `pm2 logs my-bot`, `pm2 restart my-bot`, `pm2 stop my-bot`.
Upload your files (never `node_modules`), put your `.env` on the server, then run `npm install` there.

**Safety checklist** 
- Token only in `.env`, never in code or screenshots
- `.env` and `data.json` are in `.gitignore`
- Bot permissions are minimal (not Administrator)
- Owner-only commands check the user ID: `if (interaction.user.id !== process.env.OWNER_ID) return ...`
- Dangerous commands (ban, kick) use `setDefaultMemberPermissions`
- Update with `npm update discord.js` now and then

**Troubleshooting**
- *Commands don't show:* run `node deploy-commands.js`, check `CLIENT_ID`/`GUILD_ID`, and that you invited with `applications.commands`
- *"Missing Access" / "Missing Permissions":* fix the bot's role position or channel permissions
- *"Interaction already replied":* reply only once, use `followUp`/`editReply` after
- *"Unknown interaction":* you took more than 3 seconds, use `deferReply()`
- *Crashes on an error:* wrap code in `try/catch`, and add `process.on('unhandledRejection', console.error)`

**What to build next**
- Moderation (kick, ban, timeout, logs)
- A ticket system with buttons
- Leveling or economy with saved data
- Music is complex, start with the others
- Reaction roles, giveaways, suggestions

**Where to learn more:** the official guide at **discordjs.guide** and the docs at **discord.js.org**.

**You did it!** You now know how a Discord bot is built from nothing. Keep experimenting, break things in your test server, and have fun building.
