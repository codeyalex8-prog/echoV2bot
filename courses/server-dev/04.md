# Roles and hierarchy
Roles control **who can do what** and **how people look** in the member list.

**Hierarchy:** roles at the top beat roles below them. A member can only manage roles *below* their own highest role. Your bot's role must be **above** any role it needs to give or remove.

**A solid starter set (top to bottom)**
```
Owner
Admin
Moderator
Helper
Bots           (one role per bot, or a shared one)
Staff separator ---------
Client / Supporter / Booster
Member
Unverified     (only if you verify)
@everyone
```
**Rules of thumb**
- **Least privilege:** give only the permissions a role needs
- **Avoid Administrator.** Give specific permissions instead (Manage Messages, Timeout Members)
- **Display role members separately** only for staff and key roles, not every role
- Use **colours** sparingly: staff roles a distinct colour, regular roles neutral
- Make **separator roles** (like `----- STAFF -----`) with no permissions to organise the list

**Role types you'll likely want**
- **Staff roles:** Helper, Moderator, Admin
- **Access roles:** Verified, Client
- **Reward roles:** Booster, Level roles, Event winner
- **Ping roles:** `Announcements`, `Events`. Make these **self-assignable** so no one is pinged without choosing it
- **Bot roles:** one per bot, with only what it needs

**Don't make `@everyone` powerful.** Check `@everyone` in Server Settings > Roles. It should not have Mention Everyone, Manage anything, or Create Invite unless you want that.

**Mention @everyone / @here:** disable for normal roles. Only announcement staff need it.

Checkpoint: your bot role sits above the roles it manages and nobody except the owner has Administrator.
