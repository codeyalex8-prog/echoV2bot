# Bots that power a server
Bots add features Discord doesn't have built in. Pick by **need**, not by popularity.

**Common categories**
- **Moderation and logging:** warns, bans, log channels
- **Tickets and support:** panels, transcripts, claim system
- **Roles:** button or dropdown roles, level roles
- **Welcome and verification:** greetings, captcha-style checks
- **Utility:** polls, reminders, giveaways, suggestions
- **Custom bots:** built for your exact needs (like the ones in the Bot Development pack)

**How to choose**
- Does it do exactly what you need, and nothing scary extra?
- Is it actively maintained, with a support server?
- What permissions does it ask for? Reject "Administrator" unless it's truly needed.
- Can you export or delete its data?

**Bot hygiene**
- **Invite only from official links** (the bot's website or the official directory)
- Give each bot its **own role** with only the permissions it uses
- Keep bot roles **above** the roles they manage, but **below** staff roles
- **Remove unused bots.** Fewer bots means fewer risks
- Never share bot tokens, and never give a bot you don't trust "Manage Server"

**Slash commands vs prefix commands**
Slash commands are the modern standard and show a menu. Use bots that support them, and restrict commands per channel or role in **Server Settings > Integrations**.

**Keep one bot per job.** Three bots doing moderation will fight each other and double-log everything.

**Testing a new bot**
Add it to your **test server** first, try every command, check the permissions it asks for, then add it to the real server.

**Custom bots:** if a feature doesn't exist, a developer can build it. Describe the exact flow you want, who can use it and where it posts.

Checkpoint: list your bots, what each does, and the minimum permissions each really needs.
